# Glossary

*Español: [glosario.md](es/glosario.md)*

The project's terms, in alphabetical order, explained for someone who writes iOS code but
doesn't know Cloudflare. When a note explains a term in depth, it is linked.

## A

- **App Attest**: Apple service that proves a request comes from your unmodified app. Here it
  is optional and pending: it would close the gap of a modified app that doesn't call the
  Worker (section 6.3 of the [design](DESIGN.md)).
- **ATT** (App Tracking Transparency): the "Allow the app to track…?" permission. Use for
  fraud prevention only **is not tracking**, so there is no need to ask for it. You do have to
  declare "Device ID" (and "User ID") in the privacy label, with purpose "App Functionality".

## B

- **Binding**: the way a Worker receives a Cloudflare resource. It is declared in
  `wrangler.jsonc` and shows up in code as `env.<NAME>`, like an injected dependency. Here:
  `DB` (the D1 database) and `RATE_LIMITER`. See
  [Cloudflare Worker and D1](concepts/cloudflare-worker-and-d1.md).
- **`bit0` / `bit1`**: the two bits per device that DeviceCheck stores at Apple. `bit0 = true`
  means "banned"; `bit1` is free. See [DeviceCheck](concepts/devicecheck.md).

## C

- **`check_log`**: D1 table with the result of each check (app, `ref`, blocked, bits, intent,
  date). Never identifiers or IPs. It serves observation mode and is purged after 30 days. See
  [Fail-open and observation mode](concepts/fail-open-and-observation.md).
- **Cron Trigger**: a scheduled task of a Worker, like a Unix cron job. Here it purges
  `check_log` every day. See [Cloudflare Worker and D1](concepts/cloudflare-worker-and-d1.md).

## D

- **D1**: SQLite database managed by Cloudflare. It holds the ban list, the pending unbans and
  `check_log`; one database per app. See
  [Cloudflare Worker and D1](concepts/cloudflare-worker-and-d1.md).
- **DeviceCheck**: Apple service that stores two bits per device on its servers. Survives
  reinstalls and erasing the iPhone. See [DeviceCheck](concepts/devicecheck.md).
- **DeviceCheck token**: ephemeral data generated by `DCDevice.generateToken()` that the Worker
  sends to Apple. It is not usable as an identifier and it is single-use: that is why two are
  requested (`dc_token` and `dc_token_update`). See [DeviceCheck](concepts/devicecheck.md).

## E

- **`ENFORCE`**: see *Observation mode*.
- **ES256**: the signing algorithm Apple requires for the JWT: ECDSA with the P-256 curve and
  SHA-256. The Worker signs with Web Crypto, without libraries.

## F

- **Fail-open**: if the check fails and there is no local flag, the app lets the user in
  (verdict `unknown`). A failure never kicks out normal users. See
  [Fail-open and observation mode](concepts/fail-open-and-observation.md).

## H

- **Hash**: SHA-256 fingerprint of an identifier: `SHA256(prefix:kind:value)`. It is the only
  thing stored; never the value. See [Hash and ref](concepts/hash-and-ref.md).

## I

- **`idfv`**: `UIDevice.identifierForVendor`. The same in all your apps on the same iPhone;
  changes if they are all deleted and reinstalled. See [Identifiers](concepts/identifiers.md).
- **`installId`**: UUID the SDK creates once and stores in the Keychain. Survives reinstalls; in
  the list it is the `install` kind. The app must not delete it. See
  [Identifiers](concepts/identifiers.md).

## J

- **JWT** (JSON Web Token): header, payload and signature, in base64url and separated by dots.
  The Worker creates one with the `.p8` key to identify itself to Apple on every DeviceCheck
  call, and reuses it for 30 minutes.

## K

- **Key ID**: 10-character identifier of your Apple key. It goes in the JWT header (`kid`). In
  the Worker, `APPLE_KEY_ID_<APP>`.
- **Keychain**: iOS's secure store. The SDK keeps the `installId` and the blocked flag there.
  Its items survive reinstalling the app (that is what is observed; Apple doesn't guarantee it).
- **KVS**: see *`NSUbiquitousKeyValueStore`*.

## M

- **Mutation testing**: measuring whether the tests guard the code by changing it on purpose and
  seeing whether any test fails. See [Mutation testing](concepts/mutation-testing.md).

## N

- **`NSUbiquitousKeyValueStore`** (KVS): small iCloud key-value store that syncs across the
  devices with the same Apple account. With `useICloud`, the SDK keeps the blocked flag there so
  it jumps to other iPhones.

## O

- **Observation mode** (`ENFORCE_<APP>`): unless it is `"true"`, the Worker always responds
  `ok` and records in `check_log` what it would have blocked, without writing `bit0` or
  propagating. See [Fail-open and observation mode](concepts/fail-open-and-observation.md).

## P

- **`.p8` key**: the private key file you download from Apple's portal when you create a key
  with DeviceCheck enabled. The Worker stores it as a secret (`APPLE_DC_KEY_P8_<APP>`) and signs
  the JWTs with it.
- **Prefix**: per-app text (`HASH_PREFIX_<APP>`, for example `myapp-ban-v1`) placed in front of
  the value before hashing. It keeps each app's lists apart. See
  [Hash and ref](concepts/hash-and-ref.md).
- **Propagation**: when a device comes out blocked, the Worker adds its new hashes to the list
  (`propagated`). That way the block jumps to other iPhones on its own. See
  [Propagation](concepts/propagation.md).

## R

- **Rate limiting**: per-IP request limit on `check` (20 per minute with the `RATE_LIMITER`
  binding); beyond that, `429`. Whether it works on the free plan is still to be confirmed.
- **`ref`**: the first 8 characters, uppercased, of the `install` hash. It is the support code
  the blocked user sees and the one used to unban them. See
  [Hash and ref](concepts/hash-and-ref.md).

## S

- **Secret** (`wrangler secret`): encrypted Worker value that goes neither in `wrangler.jsonc`
  nor in git. It is loaded with `wrangler secret put` and read as `env.<NAME>`. Here:
  `APPLE_DC_KEY_P8_<APP>` and `ADMIN_TOKEN`. See
  [Cloudflare Worker and D1](concepts/cloudflare-worker-and-d1.md).
- **SPM** (Swift Package Manager): apps add `NonGrata` via SPM with the repo URL, pinned to a
  version tag.
- **Strict mode**: with `strictSignup` (on by default), creating an account requires an `ok`
  from the Worker; if the check fails, the account is not created. See
  [Fail-open and observation mode](concepts/fail-open-and-observation.md).
- **Stryker**: the mutation testing tool for `worker/` and `cli/`. See
  [Mutation testing](concepts/mutation-testing.md).

## T

- **Team ID**: identifier of your development team at Apple. It goes in the JWT as `iss`. In
  the Worker, `APPLE_TEAM_ID_<APP>`.
- **TestFlight**: Apple's beta build distribution. The SDK asks for the DeviceCheck
  `development` environment only in `DEBUG` builds, so TestFlight uses production. Still to be
  confirmed with a real build.

## U

- **`userRecordID`**: the iCloud user's ID in the app's CloudKit container. In the list it is
  the `icloud` kind. Still to be confirmed that it doesn't change across devices. See
  [Identifiers](concepts/identifiers.md).

## W

- **Worker**: a program Cloudflare runs on its servers on every HTTP request, with no server to
  maintain. It decides `ok` or `blocked`. See
  [Cloudflare Worker and D1](concepts/cloudflare-worker-and-d1.md).
- **workers.dev**: the Cloudflare subdomain where a Worker is published when it has no custom
  domain. See [Cloudflare Worker and D1](concepts/cloudflare-worker-and-d1.md).
- **wrangler**: Cloudflare's command-line tool to test and deploy Workers, and to manage D1 and
  secrets. Here it is always used through `pnpm`. See
  [Cloudflare Worker and D1](concepts/cloudflare-worker-and-d1.md).
