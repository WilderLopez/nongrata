# DeviceCheck

*Español: [devicecheck.md](../es/conceptos/devicecheck.md)*

Apple service that stores **two bits per device** (`bit0` and `bit1`) on its servers, tied to
your developer account. It is the piece that makes the block survive reinstalls and erasing the
iPhone.

## How it works

1. The app asks `DCDevice.generateToken()` for a **token**. It is ephemeral and not usable as an
   identifier: two tokens from the same iPhone cannot be compared.
2. The Worker sends the token to Apple, signed with a **JWT** made with your `.p8` key:
   - `query_two_bits` returns the state of the bits.
   - `update_two_bits` changes them.
3. Apple knows which device the token belongs to; we never do.

## How we use it

- `bit0 = true` means "banned device".
- `bit1` stays free (for example, for "under review").
- Only `bit0` is sent when writing: omitting `bit1` leaves it untouched.
- **Two tokens** are requested per check (`dc_token` and `dc_token_update`) because Apple asks
  not to reuse them. If only one arrives, the Worker queries but does not write: the bit is
  written on the next check that carries both. In the meantime, D1 holds the block.

## Limitations

- Writing is only possible with a token freshly generated by **that** device: an iPhone that
  never opens the app again cannot be banned. The bit is set on its next check.
- There is no DeviceCheck in the simulator: the Worker decides with D1 alone.
- If Apple fails, the decision is made with D1 alone (see
  [Fail-open](fail-open-and-observation.md)).
- A banned iPhone sold second-hand stays banned: that is what the unban by `ref` is for (see
  [Hash and ref](hash-and-ref.md)).

## Where it is in the code

- ES256 JWT: `worker/src/apple/jwt.ts`.
- HTTP client: `worker/src/apple/devicecheck.ts`.
- Tokens in the SDK: `deviceTokens()` in `swift/Sources/NonGrata/NonGrata.swift`.
